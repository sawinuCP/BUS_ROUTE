## How to use

- Read the product vision first.
- Review problem evidence and gap analysis before feature design.
- Treat feature and technical documents as proposed design, not immutable requirements.
- Use research validation and data acquisition documents as checklists for next discovery work.
- Keep future changes in version control and record product/architecture decisions as they are made.

## Research caveat

The collection distinguishes published findings, official-source descriptions, competitor claims, illustrative scenarios and hypotheses. Exact nationwide coverage audits, hands-on competitor tests, field verification and stakeholder interviews remain outstanding.
