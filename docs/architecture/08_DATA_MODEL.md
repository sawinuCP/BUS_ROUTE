# 08 — Core Data Model

Use PostgreSQL + PostGIS. The following is a logical model; final physical schema and indexes should be refined during implementation.

## 1. Transport entities

### `transport_agencies`
- `id` UUID primary key
- `name`
- `operator_type` (public/private/rail/unknown)
- `source_id`
- `external_id`
- `active`
- timestamps

### `transport_routes`
Represents the public-facing route identity, not necessarily one unique path.
- `id`
- `agency_id`
- `route_code`
- `route_name`
- `mode` (bus/rail)
- `source_id`
- `external_id`
- `status`

### `route_patterns`
Represents a specific ordered route variant and direction.
- `id`
- `route_id`
- `pattern_code`
- `direction_id`
- `origin_label`
- `destination_label`
- `variant_description`
- `shape_id`
- `verification_status`
- `valid_from`, `valid_to`

### `stops`
Represents a physical stop/station entity.
- `id`
- `name`
- `mode`
- `location` geography(Point, 4326)
- `locality_id`
- `stop_type`
- `parent_station_id` nullable
- `verification_status`

### `stop_access_points`
Represents physical boarding/alighting access: road side, bay, platform, entrance or stand.
- `id`
- `stop_id`
- `name`
- `access_type`
- `location`
- `side_or_platform`
- `access_notes`
- `verification_status`

### `route_pattern_stops`
Ordered calls for a pattern.
- `id`
- `pattern_id`
- `stop_id`
- `sequence`
- `boarding_allowed`
- `alighting_allowed`
- `source_record_id`
- uniqueness `(pattern_id, sequence)`

### `route_shapes`
- `id`
- `geometry` LineString/MultiLineString
- `source_id`
- `verification_status`

## 2. Places and aliases
- `places`: canonical public destinations and landmarks with geometry.
- `place_access_points`: entrances and access points.
- `localities`: administrative/local area hierarchy.
- `entity_aliases`: entity type/id, language, alias text, transliteration, source, confidence.
- Add trigram/full-text indexes before considering a vector database for name search.

## 3. Transfers and walking
### `transfer_connections`
- `id`
- `from_access_point_id`
- `to_access_point_id`
- `walk_distance_m`
- `walk_geometry`
- `estimated_walk_seconds`
- `accessibility_attributes` JSONB nullable
- `verification_status`
- `source_id`
- `valid_from`, `valid_to`

Do not auto-create a transfer solely because two stops are close. A candidate may be generated by proximity and then reviewed/validated.

## 4. Provenance and versioning
- `data_sources`: owner, endpoint, format, licence, terms, schedule, adapter and enabled state.
- `source_snapshots`: immutable raw payload metadata, checksum, fetched time, storage URI.
- `source_records`: external ID, source ID, snapshot ID, raw/normalised mapping.
- `sync_runs`: status, timings, counts, errors and parser version.
- `dataset_versions`: candidate/published/rejected version, validation summary and creation time.
- `dataset_version_entities`: entity-to-version membership or versioned table strategy.
- `active_dataset`: singleton pointer to currently published version.
- `verification_records`: reviewer, method, evidence, date, status and notes.
- `data_change_audit`: before/after, actor, reason and release ID.

Choose either immutable versioned network tables or a robust snapshot/blue-green schema approach. Do not mix ad hoc in-place edits with version pointers.

## 5. Fares (optional)
`fare_rules` should include mode, route/operator/class, origin/destination or zone applicability, amount/currency, effective dates, source and confidence. Fare rules are complex; do not show a fare until its applicability is validated.

## 6. User and journey data
- `users`, `user_preferences`, `consents`
- `saved_journeys`
- `journey_sessions`
- `journey_events`
- `user_reports`
- `report_reviews`

Minimise storage of precise location history. Store journey event locations only when required and consented.

## 7. Essential indexes and constraints
- GiST on spatial columns.
- B-tree on foreign keys, external IDs, route codes, pattern IDs and sequence.
- Unique source/external ID constraints where source guarantees uniqueness.
- Check constraints for valid sequence and effective date ranges.
- Referential integrity for every pattern stop and transfer.
- Search indexes for canonical names and aliases.
