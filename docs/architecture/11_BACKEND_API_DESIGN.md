# 11 — Backend API Design

Base path: `/api/v1`. JSON over HTTPS. Use OpenAPI generated by FastAPI.

## Public endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/places/search?q=` | Search places and aliases |
| GET | `/places/{place_id}` | Place details/access points |
| GET | `/stops/search?q=&mode=` | Search stops/stations |
| GET | `/stops/{stop_id}` | Stop and access point details |
| POST | `/journeys/plan` | Generate multimodal itineraries |
| GET | `/journeys/{journey_id}` | Retrieve saved/session plan |
| POST | `/journeys/{journey_id}/refresh` | Re-plan against active dataset |
| POST | `/journey-sessions` | Start active journey |
| POST | `/journey-sessions/{id}/events` | Confirm boarding/alighting/progress |
| POST | `/journey-sessions/{id}/replan` | Re-plan active session |
| POST | `/reports` | Submit data issue |
| GET | `/preferences` | Read user preferences |
| PUT | `/preferences` | Update user preferences |

## Internal/admin endpoints
- `/admin/sources`
- `/admin/sync-runs`
- `/admin/sync-runs/{id}`
- `/admin/dataset-versions`
- `/admin/dataset-versions/{id}/validate`
- `/admin/dataset-versions/{id}/publish`
- `/admin/dataset-versions/{id}/rollback`
- `/admin/reports`
- `/admin/reports/{id}/review`

All admin endpoints require strong authorisation and audit logging.

```json
  "request_id": "uuid",
  "dataset_version": "network-2026-11-19-001",
  "generated_at": "2026-11-19T08:00:00Z",
  "availability_scope": "network_feasible_not_live_confirmed",
  "options": [
    {
      "id": "option-1",
      "summary": {
        "estimated_duration_minutes": {"min": 55, "max": 75},
        "walking_distance_m": 640,
        "transfer_count": 1
      },
      "warnings": ["Service operation has not been checked in real time"],
      "legs": [
        {
          "type": "walk",
          "from": "origin",
          "to": "stop-access-1",
          "distance_m": 220,

          "instruction_code": "WALK_TO_STOP"
        },
        {
          "type": "transit",
          "mode": "bus",
          "route_id": "route-id",
          "pattern_id": "pattern-id",
          "board_access_point_id": "access-1",
          "alight_access_point_id": "access-2",
          "instruction_code": "RIDE_TRANSIT"
        }
      ]
    }
  ],
  "notes": ["No journey found within the given constraints."],
  "suggestions": [
    {
      "kind": "nearby_stop",
      "role": "origin",
      "text": "Alternative mapped stop for the origin: X halt — 220 m away (straight-line as mapped; walking distance not checked).",
      "stop_id": "stop-id",
      "stop_name": "X halt",
      "distance_m": 220
    },
    {
      "kind": "larger_walk_cap",
      "role": "request",
      "text": "Re-plan with max_walking_m ≥ 4400 m — the routed walking-only distance is 4219 m.",
      "suggested_max_walking_m": 4400
    }
  ]
}
```

A `no_route` response may carry **adjustment suggestions** (Phase 7 item 6).
Every suggestion is derived from canonical mapped data (mapped stops,
straight-line distances always labelled "as mapped") or from a distance the
walking engine actually routed; a suggestion never claims a service,
timetable or fare and never asserts that the alternative works — the client
re-plans through the same endpoint and the planner answers honestly again.
An `ok` response carries no suggestions.

Recovery flows (Phase 7 item 5) reuse the session endpoints: the traveller
**confirms** the stop they are actually at (never auto-detected), and
`POST /journey-sessions/{id}/replan` re-plans with an optional `origin`
override; when nothing connects it answers `replanned: false` with reasons
and leaves the session untouched.

## API design rules
- Use stable internal IDs; expose source IDs only when appropriate.
- Validate request schemas and bound coordinate/radius inputs.
- Include request ID, dataset version and warnings.
- Separate network feasibility from live availability.
- Use pagination for administrative/search lists.
- Use idempotency keys for report/session creation where needed.
- Return consistent error shape: code, message, details, request ID.
- Rate-limit public endpoints and protect admin endpoints.
- Never return provider credentials or raw restricted payloads.
